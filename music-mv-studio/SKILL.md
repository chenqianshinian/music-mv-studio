## 1. 核心原则（违反必返工）

1. **先理解叙事，再写分镜。** 歌名＋歌词决定主角是谁、空间如何转换。任何"主角会飞／会变身／会拟人"的设定，先向用户确认。
2. **镜头逻辑＝真实世界逻辑。** 比例、解剖、动作连续性（起-中-落）都要能自圆其说；分镜要像纪录片一样讲得通。
3. **动态优先。** 每段必须是"会动的视频"；抽帧测帧间差 <8 判为静态，必须重生成。
   **例外（2026-09-25 实测修正）**：`fps=8` 灰度帧间差均值这一个口径**卡不住慢运镜**——
   已交付并获用户认可的 i2v 空镜实测就有 3.13／5.10／7.80 落在 8 以下。
   判"静态"必须以**累计位移**为准（首帧 vs 末帧的整体位移是否看得见），
   帧间差只用来抓"顿帧/冻结段"（连续多帧 <1.0）。混血运镜见 §11.1。
4. **垫图宁多勿少，但第二帧必须派生。** 复杂动作 3–4 帧；**第二关键帧从第一帧 i2i 派生**，不要两次独立生成（独立生成会让模型在两张之间插值 → 双头／鬼影）。
5. **同一画面反复出现＝空洞。** 同一角色同一视角的特写全片 ≤2 次；重复歌词必须换场景／景别／机位／光。
6. **表情按角色卡写死**，禁止咧嘴大笑类恐怖表情。
7. **数字资产只锁一张脸。** 双人题材让"被看的那个人"承担全部面部资产，另一个人的正脸全片 0 次（背影/手/肩出场）——既贴视角，又把崩脸风险砍半。

## 2. 导演设计五层（每首歌开工前逐层过，2026-08-17 用户严厉批评后确立）

**病根（两次犯过，别再犯）**：用"流水线思维"替代"导演思维"——每句歌词直译成一个画面、默认给特写（特写最易生成），导致人物关系／场景关系／景别节奏／视角切换全缺，MV 碎片化、怼脸化、业余化。

### 第 1 层 叙事设计（先写，不写不分镜）
主角卡（外貌/年龄/处境）、人物关系（几人、什么关系、如何变化）、时间线、空间线（空间是情绪的容器）、情绪弧线（起-伏-转-合，精确到时间点并对应歌词）。

### 第 2 层 镜头语言
- **景别配比**：**特写 ≤20%**，只在情绪爆点用；大远景/远景先建立空间，中/全景表达关系。
- **视角 ≥2 种**：主观（人物看到什么）／客观（我们看人物）／大远景（人在天地间的位置）／微观（贴地细节）。
- **运镜语法**：推/拉/摇/移/跟/固定各自承担什么情绪，何时静何时动。
- **蒙太奇**：平行／交叉／隐喻／对比用在哪几处；重复歌词用"同构图换光"做时间切片。

### 第 3 层 人与环境比例
情绪孤立渺小时人小环境大（人占 1/6–1/8）；亲密关键时人大环境小。**空镜不是装饰，必须承载情绪**；每个含人物的镜头都要写明人物在画面里的位置与占比。

### 第 4 层 人物一致性
外貌卡、**衣着/状态随情绪变化**（不是一套衣服穿到底）、专属小动作、这个角色如何表达情绪（克制型／外放型）。
**人物卡必须按镜注入（CHAR_MODE）**，负向词随模式自动切换，从结构上杜绝"正向要人物／负向禁人物"的自相矛盾。参考模式集：`NONE / HANDS / SHE_FACE / SHE_EYES / SHE_HAIR / SHE_PART / HIS_BACK / BOTH_BACK / BOTH_SIL`（"她/他"按歌替换），每首可裁剪。

### 第 5 层 歌词转译
歌词是叙事单元不是字面配图；相邻有因果/连续动作的句子**合并为镜头组**（连续动作流）；重复歌词换场景/景别/视角/时间；**禁止"每句歌词一个独立特写"**。

### 交付前自检（任一项不过关不开工）
1. 导演稿含第 1–5 层，不是只有分镜表；2. 特写 ≤20%；3. 含人物镜头都标了环境占比与视角；4. 人物有衣着/状态变化；5. ≥3 种景别、≥2 种视角；6. **逐镜人物卡（CHAR_MODE）齐全且与正向描述不冲突**。

| 合成 | `compose_zuindongni.py` | 字幕最大宽度自适应 `CAP_MAX_W`；副歌进入处**硬切**、同段链式镜用 0.30–0.35s 交叉淡化；`ZDN_FADE_OUT="起秒,时长"` 做结尾渐黑；环境变量 `ZDN_BANK/ZDN_CLIPS/ZDN_OUT`（**全曲合成必须显式传 full bank，否则会默认读小样 bank——日志首行会打印 shots 计数**） |
| 合成收尾核验 | `render.log` 的 polish 行 | 合成结束会自动做「镜头素材内部硬跳变 → 定点补溶解」。**必须看这一行：`硬跳变 0 处` 才算过**；非 0 说明素材内部本身有突变，要到出问题的那条 clip 上重出（见 §9） |
| 驱动 | `run_<歌名>.py` | 组装→合成→质检→交付 四步幂等驱动，`ZDN_VER=v3/v4/…` 决定版本命名，`--step NN` 单步跑。**单步模式不要写 DONE.ok**（否则"质检跑完"会被当成"整片交付完成"） |
| 省时间的关键 | 按帧号定点重渲染 | 合成器按帧号缓存 JPEG（`<项目>\work\out\%05d.jpg`）。只改字幕/颜色时：把受影响 cue 时间窗内的帧**移走**（不要删，可回退）再原样重跑，其余帧复用。**绝不能用 `--fresh`**（会全片重抽） |

## 4. 验收（交付前逐条做，用像素说话）

1. **首帧闸门**：先只跑 `--kf-only`，逐镜看首帧（**拼图看全局 + 单张全尺寸看文字 + 局部放大看手脚**）——过关才跑视频。
2. **视觉验收通道**：`agnes-3.0-flash`（便宜且准）抽帧读景别/机位/构图/词义匹配分，汇总统计。
3. **密集帧扫描**：每镜抽 7 帧（不是只看中间帧）——崩坏集中在关键帧之间的插值区。
4. **像素级字幕校验**：`qa_captions.py <成片> <srt> 1580`，统计字幕带（y 1490–1670）亮字像素占比；每条 cue 都要有峰值，无字幕段应接近 0（画面本身亮部会误报，需抽帧确认）。
5. **总览与全尺寸复核**：`grab_frames.py` 出 30 帧总览；用 `ask_image.py` 单张全尺寸读字（**缩略图/拼图会让视觉模型幻觉出并不存在的文字**）。
6. **颜色/可读性取样必须取 cue 中点**，不要取起手淡入帧（淡入中 alpha 不为 1，会误判成"没生效/偏色"）。
7. 分辨率/帧率/音轨/时长 + 尾声渐黑实测（成品文件出现 ≠ 渲染完成，**必须以日志出现 `MV DONE` 为准**，封装中文件已存在但 moov 未写完）。
8. **素材内部突变扫描（v2.1 新增，交付前必做）**：对 clips 目录里每一条镜头单独跑 `ffmpeg -i shot_X.mp4 -vf "select='gt(scene,0.10)',metadata=print" -f null -`，任何一条在自己的**被用到区间内**报出突变点，就该镜重出——它是"画面突然顿一下/换个姿势"的根源，微调字幕或补溶解都救不回来。
9. **补溶解复核**：看合成日志的 `polish:` 行，必须是 `硬跳变 0 处`。若报了窗口，去对应帧号（`帧号 = 秒 × 30`）抽整尺寸帧看——补溶解是把跳变前后**各一张静止图**做交叉混合，效果是那 0.5–0.7 秒几乎不动（帧间差从 ~10 掉到 0–3.4），观感"顿住"，比原来的硬跳变更扎眼。
10. **方向与人数复核（v2.1 新增）**：每个动作镜交付前，用 `check_clip_heads.py` 数一遍人头，并用视觉模型按固定字段回答"行进方向＝持续向前／出现倒退倒放／原地踏步"；单车类镜头额外问"后座的人双脚是踩踏板还是放在车架上"。**方向问题一旦出现在首帧，重出才有用，不要去改字幕或加转场掩盖。**
11. **字幕阈值兜底**：`qa_captions.py` 默认按 `min(R,G,B) > 180` 判亮字。暖木色/暖墨色字幕（如 `(240,206,158)`、`(236,208,160)`）最暗通道只有 ~158，会被**假报 0%**。出现 0% 先把阈值降到 140 复测，再说"没有字幕"。

### 9.3 方向问题的五个抓手（按力度排序）

1. **首帧**——最强。首帧朝镜头骑，后面 3 秒必然朝镜头骑。

### 9.6 第二轮实验：方向锁有效，景别比例锁无效（2026-09-24 12:07，A1-10 实测）

A1-10（远景、两人骑车离去）实验数据，值得记住这组对比：

- **第一轮**（提示词里方向句在中后段、只在末尾补了方向锁）：3 条候选**全部**"面朝镜头、朝镜头骑来"，单张全尺寸复核与四帧语义判定两种口径一致。
- **第二轮**（三处改动：①把"朝巷子深处骑去、背离镜头、两人只是小剪影"提到 i2v 提示词**第一句**——这样 `derive_kf1()` 也顺带吃到方向描述；②该镜单独补方向类 negative_extra：`朝镜头骑来, 面向镜头骑行, 倒放, 倒退, 车轮倒转, 车辆倒滑, 人物放大成中近景, 清晰正脸`；③删掉 kf1x 让它按新第一句重派生）：3 条候选里 **2 条方向纠正为"背对镜头骑向画面深处"**，选中的那条前后段都无清晰正脸、素材内无突变、无持续冻结。

**结论（要改掉之前的说法）**：

1. **方向**：提示词层的【方向锁】＋方向类负向词 **确实有效**（这一组从 0/3 变成 2/3），前提是把方向句放到**第一句**（模型对开头敏感，且 `derive_kf1` 只读第一句）。
2. **景别比例**：仍然无效——三轮下来这一镜始终是"人占画面 1/2"，写"不超过 1/10"也不听。景别／比例类约束**不能只靠提示词**，要么接受实际景别，要么换镜头设计（见 9.3 第 5 条的兜底）。
3. 因此 §9.1 里"A1-10 的根因是首帧"要更精确地说：那一镜的首帧确实也错过一次（两人面朝镜头＋占 1/2），**但换成背向小剪影的首帧后，视频模型仍然无视了首帧的景别、甚至无视了方向**——所以「首帧锁方向」是**必要条件不是充分条件**，动作镜必须首帧锁＋第一句锁＋负向词＋多候选择优四件一起做。

### 11.1 混血运镜：无人物空镜不走 i2v，走确定性 2.5D

> **⚠️ 2026-09-25 v2.4 就地更正（本节结论已被推翻，请按更正后的口径执行）**
>
> 用户看完《两岸统一》v1（61 镜确定性 2.5D ＋ 39 镜 i2v）后的原话：
> 「**静态图帧插入的有点多，很多河流、海鸥、鸟雀、烟雾、雪的镜头都不动，微风拂过一些轻一些的东西
> 应该要有自然的物理运动呈现效果，那么多静态图的表达效果确实差……疑似幻灯片了**」。
>
> 下面那段"落在同一档位、不会比现在更死"的论证**在数值上没错、在观感上是错的**：
> 帧间差均值把"整幅画面位移 3.49"与"水面在流动 3.13"当成了同一件事。**确定性运镜只有相机位移，
> 画面里没有一个元素在自己的物理规律下运动**——河流不流、海鸥不飞、烟不散、雪不落、草不动。
> 观众看到的不是"安静的镜头"，而是"一张静止的画被慢慢放大"。
>
> **更正后的口径（v2 起）**：
> 1. **100 镜一律走 i2v**，不再按 `_char_mode` 分派渲染方式；
> 2. 每镜的 `i2v_prompt` 由生成器机械注入 **【运动锁】**——按内容关键词匹配要动的物理
>    （水面起伏／浪花拍岸退去／雾与云推移／烟与热气上升飘散／细雪飘落／鸟群振翅掠过／灯火摇曳只亮不灭／
>    雨丝与檐滴／枝叶衣物被风吹动／人影持续同向移动），并写死"**不新增任何元素、不改变物体数量与位置关系**"；
> 3. 同时补 **【结构锁】**（数量/外观/衣着/朝向不变）与运动类负向词（画面扭曲、形变、融化、结构崩坏、卡帧静帧、倒放、倒退）；
> 4. **确定性中心放大（`make_kf1_zoom.py`）与 `still_move.py` 不再用于正式镜头**，只保留两种用途：
>    ① 第二关键帧兜底（派生帧反复丢人/加人时，用它保证首尾两帧人数结构 100% 一致）；
>    ② 单镜返修时的临时替代。
> 5. 判"动没动"**不要再用帧间差均值**（见血泪 #18 与本更正）：要问"**画面里哪个元素在动**"，
>    最好直接看该镜的抽帧序列问视觉模型。

#### （以下为 v2.2 的原始论证，保留作为"当时为什么这么决定"的记录）

**规则**：分镜库里 `_char_mode == none` 的镜（空镜/风景/静物/光影），**默认不做 i2v**，
改用「静图 ＋ 确定性 2.5D 运镜」。只有含人物、含动作、含物理交互的镜才走 i2v。

**为什么**（这是五首歌反复吃亏的那一类问题的**根治**，不是缓解）：

- i2v 在无人风景镜上的收益只有"云动/水动/光变"；代价却是我们一直在吃的坑——
  派生帧凭空加人、派生帧把人物丢掉、运动方向反、素材内部突变、每镜 2–4 分钟与 429 队列。
- 确定性运镜没有插值、没有随机性，**从原理上不可能产生"多一个人/少一个人/方向反"**。
- 实测同口径对比（`fps=8` 灰度帧间差均值，《两岸统一》静态帧 vs 已交付的 i2v 空镜）：
  确定性 `drift` 3.49 / `push` 3.33 / `pan_right` 2.00；
  《海边日落》已交付 i2v 空镜 B1 **3.13**、V1-1 5.10、D1 7.80、B10 9.53。
  **落在同一档位**——最"静"的那条 i2v（3.13）与我们几乎一样，用户当初是认可的。
  也就是说换成确定性运镜**不会比现在更"死"**，却省掉整类 bug 与生成时间。
- 速度：5 秒镜头确定性渲染 **约 1.3 秒**（实测三条共 4 秒）；i2v 是 2–4 分钟/镜且要过 429。

**工具**：`work\still_move.py`（移植进 `scripts/` 时改路径）

```
python still_move.py <静图> <输出mp4> [秒数=5] [push|pull|pan_left|pan_right|tilt_up|drift] [fps=24]
```

- 六种运动都是 `ease-in-out`（`0.5-0.5*cos(PI*t)`，起止速度为 0，不会"起步一顿/末尾一顿"）。
- 先 `scale` 到 3 倍再 `zoompan`，避免整数像素取景造成的抖动。
- **可复现**：无随机数，同参数两次渲染 **MD5 完全一致**（已验，两版 `B176A308…`）。
  这意味着以后"改字幕/改色不影响画面"可以**用哈希证明**，不必再靠视觉模型估。

**留白与呼吸**：确定性运镜天生安静，正好承载空镜的情绪停顿；不要因为"能动"就加满运动。
要"活"起来时**加程序化图层**（云/雨/雾/光斑/水波），不要倒回去找 i2v。

### 11.2 镜头卡化：验证过的镜头要固化，不许每首重掷骰子

video-shotcraft 最值得学的是**形态**：它的 157 张卡里，卡是「语义＋参数表」，
真正的调校真相在配套 demo 源码里，而且**卡上标了"已知坑/命门"的参数不得降档**——
"凭卡名和自己理解重新写＝放弃全部调校积累"。

我们的对应物是分镜库里那一串提示词，但**每首歌都是重新生成的**。改法：
**验证过的镜要落成卡**。每首交付后，把当次"一遍过、零返修"的镜抽出来，按题材归档：

```
cards/<题材>/<卡名>.md      # 一行适用条件 + keyframe_prompt + kf1_prompt + negative_extra
                            #   + 锁定条件（人物卡/方向锁/结构锁）+ 那一次的验证结论与参数
```

下一首遇到同类（海峡明月、老厝门框、雨夜街角、庙会人群…）**直接引用卡并按卡改**，
允许适配，但卡上已标注"命门"的参数不得降档。**这是"越做越快、越做越稳"的唯一机制**。

### 11.3 独立终检：交付前让"干净上下文"的 subagent 审一遍

它的理由是原话：**"制作者对自己的产出有确认偏差，首检永远不能交给用户。"**
我们的对应纪律：

- 交付前派一个**没有参与制作的 subagent**（不共享本轮的判断过程，只给它成片、抽查帧、
  分镜库、字幕、以及"这一首要达成什么"），按固定字段逐条出带**帧号证据**的结论。
- 审查输入必须含"当时的设计意图"——否则它只能评价好不好看，无法判断**有没有做到**。
- 这条是直接治我们的老毛病：`A1-10` 目视过关、`M-3` 以为单人，都是"自己看自己"漏掉的。

### 11.4 卡点校验：切点要能被回测，不靠感觉

它的做法（`music-beat-sync`）：**先用 librosa 拟合真实 BPM/相位 ＋ 三分鼓点定位，
网格按瞬态覆盖率验收通过后才分镜**；时间线用拍号写，**渲后从成片抽音轨回测切点误差 ≤3 帧**。

我们的现状是按字幕 cue（即人声）切镜，节奏感来自经验值（主歌 2.5–2.8s/镜）。补上：

1. 分镜前跑一次节拍网格，把**副歌进入、情绪转折**这几个关键切点钉在真实瞬态上；
2. **交付前回测**：从成片抽音轨，核对关键切点与最近的鼓点/瞬态之差，>3 帧的记下来复盘。
3. 我们的卡拍**只管时机不管幅度**：作用于整画面的节拍冲击全片 ≤3 处，其余只动元素层。

### 11.5 顺带给 §10 开源清单加一条

video-shotcraft 的可信度有一半来自**工程完成度**：双语 README ＋ 徽章 ＋ 在线动态样片画廊 ＋
分层 `references/` ＋ 独立终检 ＋ LICENSE ＋ 贡献指南。§10.1 的 6 件之外，加：

- **一张"动态样片"清单**：不是截图，是可点开的短片（哪怕只在 README 里挂几个链接）。
  读者看 30 秒比读 3 千字有效——我们的"首帧总览＋30 帧质检总览"是内部证据，不是对外展示。

## 12. 首帧闸门"不合格"分五类，各有确定性修法（2026-09-25《两岸统一》实证，v2.4 增补第五类）

首帧质检报出的"不合格"**不要一律返工重出**，先分类（《两岸统一》第二轮曾一次报 31 镜，逐条核对后大半不是画面错）：

1. **规格自相矛盾 → 改规格，不重出图**：`_char_mode` 与镜描述要求的人数不一致（描述要人群剪影/采茶人影/操偶的手/窗影两个轮廓，模式却写 `none`）。
   做法：从描述反推模式（补 `crowd_sil`/`both_sil`/`face_plus_back` 等档），负向只锁"清晰五官/正脸"，**不锁"人物/人影"**。
2. **派生帧丢人/加人 → 换机制**：用 `make_kf1_zoom.py` 生成确定性第二关键帧（首帧中心放大 96%），不用 i2i 重掷（见血泪 #23）。
3. **手部镜边缘露脸 → 确定性裁切**：`crop_top.py <比例> <png...>`（按比例裁上边 + 等比缩放、不变形；手部镜 12%、只剩 0~1% 下颌轮廓的 8%），裁完复检头数（见血泪 #24）。
4. **画面里出现文字/数字 → 逐镜 `PROMPT_EXTRA` + 逐镜负向**（见血泪 #25）。
5. **画风被判成 3D/写实 → 先开放式追问确认，再抽卡择优**（v2.4 新增）。单字母画风标签会翻转（血泪 #30），
   先用"用一句话描述画风＋判断依据"复核；确认偏写实/3D 时**不要只加负向词硬试**，而是同一内容用 3 版
   "强二维"提示词各出一张（写死"赛璐璐平涂、清晰墨线描边、纸底、最多四种平色、不要写实材质/景深虚化"），
   再用开放式追问选最二维的那张（`ka_a21.py`：《两岸统一》A2-1 一次抽卡就通过）。
   还要注意**引起写实的往往是题材本身**：A2-1 第一次把"书法条幅"写进画面，既出了伪汉字又拉成 3D；
   把书法条幅换成水墨远山长卷后两个问题一起消失（血泪 #25/#30）。

执行层工具（都在会话 `work/` 下，可跨歌复用）：`make_lianan_bank.py`（分镜库生成：模式档/人数锁/方向锁/逐镜补充）、
`lianan_kf_verify.py`（可数口径自检：几个头/几只手/画风 A-D/有无文字，`--force` 重判）、`make_kf1_zoom.py`（确定性派生帧）、
`crop_top.py`（确定性裁边）、`ask_batch.py`（批量定向追问并把结论写成 UTF-8 文件，避免控制台编码把汉字弄乱）、
`lianan_kf_sheet.py`（首帧总览拼图，交用户看片）。**旧帧一律移进 `_rejects/` 存档，不删除。**

## 13. 提示词的两条新纪律（2026-09-26《两岸统一》v3 实证，v2.5 增补）

### 13.1 【运动锁】只写画面里真实存在的元素

锁的作用是"让已有元素动起来"，不是"让模型补元素"。i2v 把提示词当**画面清单**读：
写到什么，它就可能画什么。所以拼锁时必须**先读该镜的画面描述，再逐条只留画面里已有的东西**：

```
画面有：雨幕、伞、手        → 锁：伞面水珠顺着伞骨滴落一两滴；廊外远处雨幕持续下落
画面没有：灯笼、树、人群     → 一律不许写"灯笼摇晃""枝叶被风吹动""人影移动"
```

自动拼锁的模板里**禁止出现**这些会凭空长元素的通用句：
`画面里的人影持续朝同一方向移动` / `鸟群持续振翅飞行` / `灯笼轻轻摇晃` / `枝叶被风吹动` / `人群攒动`。
空镜（`_char_mode=none`）尤其致命——它会把剪影镜变成"多出几个人"的穿帮镜。

**开工前必做**：`_v3_scan_locks.py` 式全库扫描——逐镜比对「锁里提到的元素名」与「该镜画面描述里的元素名」，
不在画面里的名字全部报出来人工裁定。《两岸统一》v2 扫出 42 镜，逐镜改完才重出。

### 13.2 改提示词要改"模型真正读到的那一份"

分镜库里每镜的首帧提示词在 `keyframe_prompt` 和 `keyframes[i]` 里各存一份，
**生成器读的是 `keyframes[i]`**。改 `keyframe_prompt` 是无效改动（本轮四镜发髻就是这么白改一轮）。

> 通用做法：改完立刻回读断言 `'旧词' not in keyframes[i] and '新词' in keyframes[i]`，
> 断言不过就别提交生成——一次全白的首帧要 1 张图 + 1 次派生 + 1 轮闸门才能发现。

### 13.3 字幕按"演唱断句"揭示，不要整句 cue 一起亮

用户 2026-09-26 原话：「歌词字幕的出现与演唱断句、换气似乎没联系起来，该换行显示的后面的句子
为了长度在屏幕显示合适却提前出来了」。做法：

1. `_align_lyrics.py`：把**文档歌词逐行**对到 ASR 的行级时间轴上（《两岸统一》81 行/408 字、匹配 100%、插值 0 行）；
2. `make_lianan_clauses.py`：每条 cue 拆成 `clauses=[[句,起唱,唱完], ...]`，
   **顺带修掉"合并 cue 被截断"**——合并规则有跨度上限（6.0s），会出现"字幕止于 31.82s、实际唱到 34.30s"，
   这种 cue 要另存 `eff_start/eff_end` 当显示窗口；
3. 合成器 `compose_lianan.py` 接 `ZDN_CLAUSES`：**逐句淡入、正在唱的行最亮、唱过的行压暗 0.78、行距 104**；
   **不设该环境变量时完全保持旧行为**（其他歌不受影响）；
4. 生成前用 `_v3_caption_preview.py` 在**真实成片帧**上把新字幕画出来自检（截 34.6s「只显示第一句」与 38.2s「三句齐」两张，
   单张全尺寸看有没有裁边/乱码），再进合成。

### 13.4 解剖锁 + `src_offset`：飞行/游动主体的畸形只在运动段

**现象（2026-09-26《两岸统一》v3→v4，用户原话「2分48S-2分49S的海鸥头尾交错的像长在了一起」）**：
A8-3 单只海鸥贴水掠过，**首帧 `kf_A8-3_0.png` 与派生帧 `kf1x_A8-3.png` 都完全正常**
（1 只、滑翔掠水、无双头无头无尾），但 i2v 素材自己的运动段是坏的：
0.6s 无头无尾、0.9s 双头／头身错位、1.2s 多翼＋腿从侧后部伸出、2.4s 头身轮廓不清、
3.5s 翅膀下方多出黑色块状、4.0s 双翅融合成单一弧形——成片 168.6s／168.9s 就是这团东西。
**这类畸形没有任何一张关键帧能反映，所以「首帧闸门」（含派生帧）100% 会放行。**

**修法三件套**：

1. **【解剖锁】**（写进该镜首帧与 i2v 提示词，用排他式）：
   `头始终在身体前方且带动脖子朝前、尾巴在身体后方、双翅各一片对称长在两侧；绝不头尾连成一体、绝不融合成一团、绝不出现双头／无头／无尾／翅膀粘连／尖刺状翅膀／多余的翅膀或多余的腿。`
2. **解剖类负向词**：`双头, 无头, 无尾, 头颅缺失, 头身融合, 身体融合, 身体扭曲成一团, 翅膀粘连, 翅膀融合, 多翼, 多余的翅膀, 多余的腿, 解剖错误, 畸形, 尖刺状翅膀, 脖子折叠`
3. **`src_offset` 掐头**：合成器按分镜库字段跳过素材开头那段过渡——`compose_lianan.py` 的取帧口径改成
   `t = (t - st0 + lead + float(shot.get("src_offset", 0) or 0))`，**缺省 0 时行为与旧版完全一致**
   （其他歌不受影响）。A8-3 换两条候选后开头 0.3-1.0s 仍有畸形，最终取 `src_offset: 1.2` 直接跳过。

**验收纪律（新增）**：飞行／游动类主体（鸟、鱼、虫、飘动的花瓣与纸片）**不能只看首尾帧**，
必须**多抽素材中段帧**用视觉模型逐张问「有没有可辨认的头／尾／翅，身体有没有揉成一团、有没有双头」。
中段帧全干净才算过；有畸形就先换候选，换不掉再用 `src_offset` 掐掉那段。

### 13.5 镜窗要锚定「演唱断句」，不要用均匀网格

**现象（2026-09-26《两岸统一》v4 → v5，用户原话「22-23S 这边是故乡月，那边是游子衣，
歌词和画面匹配有点错位感」「从 16S-45S 的歌词和画面匹配都顺着错位了」）**：
「这边是故乡月」20.96-23.08 在唱时，月亮镜已经结束了（镜头 18.52-21.19）——月亮只赶上这句的 0.23s。

**诊断（可复用，几乎零成本）**：分镜卡里本来就写了「本镜要对上的那句歌词」（`_note` 里的「」引文），
把它与 `clauses.json` 的逐句起唱时间逐镜比对（本例 `_diag_note_offset.py`）：
**47 个可比对镜里 35 镜偏差 ≥1s**，规律是 **「每一段段首对齐、段内是均匀网格」**，
而歌词句长在 1.7-5.0s 之间浮动，于是段内越走越偏：段首 delta≈0，段中最大早 5-9s。
用户那句「是不是从『一湾浅浅的海峡』开始画面时长不够，导致后面都错位」直觉是对的，
真正的机制是「网格步长 vs 句长」。

**修法**：以 `clauses.json` 的起唱时间为锚，重排镜窗——**那句歌词一开口，对应画面就上**：
有对应句的镜 `t0 = 句起唱`；没有对应句的空镜／地标镜／手部镜在两侧锚点之间按镜数均分；
个别镜需要与时位互换才能落到正确的那句上（本例把「孔庙香炉」镜与「大学校门」镜换位，
让孔庙香炉正好落在「孔庙的香火延续」）。

```
python _diag_note_offset.py          # 先出偏差表，确认是网格问题而不是内容问题
python _propose_retime2.py           # 提案：硬锚点 + 可信软锚点 + 槽长上限
python make_<song>_timeline.py       # 写新分镜库（旧库不动）
python _move_lianan_window.py        # 只把要重画的那段帧移走，其余复用（本例 1466/8218 帧）
```

**红线（重排时必须同时满足）**：
1. **单槽 ≤ 约 4.5s**：合成器里素材按 1:1 取帧，超出素材长度后末尾只做轻微放大兜底
   （上限 1.18×），槽再长末尾就成静止画面——用户最反感的「幻灯片感」会立刻回来；
2. **单调**：重排后逐镜 `t0` 必须严格递增（脚本里加断言）；
3. **段首与段尾不动**：段首（歌词与画面本来就对齐的点）与整段总长保持不变，
   只重分配段内；这样镜像与字幕时轴都不用动。

**实测效果**：重排后 A1／A2 两段所有镜 delta=0、槽长 1.36-3.89s；
「这边是故乡月」整句都在月亮上、「那边是游子衣」在台北雨夜那件淋湿的外套上、
「举杯少一席」在两只茶盅（一只空着）与月饼上、「孔庙的香火延续」在孔庙香炉上。

### 13.6 同一解剖畸形反复复发要改设计；i2v 素材要逐帧可数扫描

**案例（2026-09-26《两岸统一》v5 → v6 → v7，用户两次点名）**：
用户先截 2:49 的图说「海鸥还是没处理好……还是头尾都在」；我过全片同族镜时又发现 3:59 的月前海鸥
「月亮前两只鸟身体/翅膀粘连成一体、还有鸟朝相反方向飞」。

**根因（可复算）**：
1. A8-3（2:49 海鸥近景）——v4/v5 用的 `shot_A8-3_1.mp4` **整条素材都是坏的**：
   0.5s／1.0s／1.8s／3.0s／3.3s／3.8s／4.0s／4.3s／4.5s／4.8s／5.0s 全部报「2 头 2 喙」；
   **而它的首帧 `kf_A8-3_0.png` 与派生帧 `kf1x_A8-3.png` 都是干净的 1 头 1 喙**——
   即畸形完全由 i2v 运动段自己编出来（§13.4 的加强：**不只是开头过渡段坏，中段一样会坏**，
   上一轮「素材中段是干净的」的结论是错的，原因就是当时只抽了三四帧）。
2. A11-3（3:59 月前海鸥）——三条候选**都有**鸟在月前粘连；这是「多鸟同框 + 深浅遮挡」的结构性问题：
   视觉模型分不清「一只挡在另一只前面」和「两只长在一起」，而用户的眼睛会把它看成穿帮。

**修法**：
- A8-3：换成 `shot_A8-3_0.mp4`（逐帧 1-102 全干净，只用到 1-83 帧），去掉 `src_offset`，只重画 123 帧；
- A11-3：**改设计**——从「圆月与 3-4 只海鸥同框」改成「月前只有一只极小的海鸥剪影」
  （单主体 ⇒ 结构上不可能粘连、不可能方向不一致），新首帧＋派生帧重出、i2v 重出 3 条候选择优；
- 两次都只重画受影响窗口帧、复用其余帧缓存（每次约 1.5 分钟），成片另存新版本，旧版一律保留。

**扫描纪律（本轮新立的硬门）**：
```
python _gull_scan_par.py <素材mp4> <tag> <step=1> <crop=full|gull> <workers=1>   # 逐帧可数扫描，落盘可续跑
python _gull_zoom_ask.py <单帧图> gull "画面里有几个头？几个喙？"                    # 放大裁切＋自定义问法复问
```
1. **只扫「合成真正用到的帧区间」**：`local = (合成时刻 - 该镜 t0 + LEAD + src_offset) × fps`，
   本例 A8-3 的窗口只需素材第 1-83 帧；
2. **不准抽样**：上一轮抽样（每 8 帧问一次）漏掉了中段的双头，导致结论反了；
3. **全帧问法会假报**：俯冲姿态的海鸥被判「0 头」（其实头朝下被身体挡住），
   月前的极小海鸥被判「无鸟」——**任何可疑/存疑帧都要用放大裁切＋换问法独立复问 3 次**，
   三次都同向才算结论（本例 v6 的 169.5s「1 头 2 喙」三次复问全是 1 头 1 喙 ⇒ 判为误报）；
4. **Agnes 免费档并发即挂**：8 并发会让请求全部挂死（不返回也不报错），扫描脚本必须**串行**
   （`workers=1`＋每帧 1.2s 间隔），121 帧约 20 分钟；
5. 反面教材：像素级的「橙黄色块计数」与「月盘内暗块质心追踪」在本片都没能区分干净帧与畸形帧
   （浪花/暖色高光会产生一堆小色块；剪影在暗天空里根本不成暗块），**不要拿它们当定性依据**。

**交付口径**：换素材改了窗口 ⇒ 只重画该窗口的帧（`_move_lianan_window6.py`／`_move_lianan_window7.py`
把窗口帧移进 `out_vN_window_old\`，不删除），再跑收尾驱动的 04/05/06 三步即可（合成整片编码约 1-2 分钟）。
