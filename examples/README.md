# 分镜库字段说明

这份文档给**想写自己第一份分镜库**的人：以 `examples/song-a-bank.json` 为范本，逐字段说明
"填什么、必填还是可选、填错会怎样"。范本是虚构的（虚构歌名、示例歌词、4 个镜），
真实项目里 `shots` 会有几十到上百个。

写完之后怎么用：`python scripts/gen_zuindongni.py --bank <你的库.json> --outdir <中间产物目录>`
出关键帧与片段，`python scripts/compose_mv.py` 按同一份库拼成片（`ZDN_*` 环境变量的设法见
`.env.example` 与 `README.md`）。想先不花钱验证环境，直接跑 `python tests/smoke_offline.py`。

## 顶层字段

| 字段 | 必填 | 说明 / 填错会怎样 |
| --- | --- | --- |
| `_comment` | 可选 | 写给读的人看的备注（库怎么来的、哪几句对哪几镜）。**脚本从不读它**，写错不影响运行。 |
| `_meta` | 可选 | 全库共用的风格、字幕色板与角色卡，见下一节。缺了就走脚本内置默认值（写实风格、内置示例角色卡）。 |
| `negative_prompt` | 必填 | 全库负向词。生成器把它拼进每镜的 i2v 请求（逐镜的 `negative_extra` 追加在后面）。少写一类的代价见 `SKILL.md` §6.3——**运动类最容易漏**，一漏"倒退/倒放/原地踏步"这类方向畸形就会一路反复，且每轮都要重出素材。 |
| `shots` | 必填 | 镜头数组。生成器与合成器都在第一行取 `bank["shots"]`，缺了这个键直接崩。 |

## `_meta` 字段

| 字段 | 必填 | 说明 / 填错会怎样 |
| --- | --- | --- |
| `style_prompt` | 可选（强烈建议写） | 这一首的画风串。**风格必须前置**：把它写在每镜提示词的**开头**（`SKILL.md` §6.1）——写在句尾时模型会先按题材画成写实或 3D，风格被忽略。它同时替换生成器内部的风格串（定妆照提示词用的是它）。不填时沿用内置的"写实电影摄影"尾巴，国风动画/沙画这类库会被带成写实；只填了 `_meta` 却没把它抄进 `keyframes` 的开头，逐镜提示词照样是"无风格"。 |
| `kf1_style` | 可选 | 第二关键帧（i2i 派生）提示词的收尾风格串。派生帧是在首帧上"往前推一点"，风格漂移会在这里最明显。不填时沿用内置的写实串，二维库常见后果是：首帧是平涂，派生帧往写实跑，插值出来的视频两头画风打架。 |
| `caption_colors` | 可选 | 字幕"情绪色"锚点，格式 `[[秒, [R,G,B]], ...]`，如 `[[0.0,[232,240,250]],[6.0,[248,236,214]]]`。合成器在相邻锚点之间**连续插值**（不是跳变）：第一个锚点之前用第一个颜色，最后一个锚点之后用最后一个颜色。优先级是 分镜库 > `ZDN_CAPTION_COLORS` 文件 > 中性暖白。填成对象（`{"0": [...]}`）或 `"#FFFFFF"` 这类字符串，合成器按 `for t, c in raw` 解包时直接崩；锚点时间不递增，插值会拿到反向斜率、颜色跳在错误的时刻。 |
| `ids` | 可选 | 角色卡：`{"角色名": "定妆描述"}`，每个角色出 2 张候选定妆照。**显式写 `"ids": {}` 表示跳过定妆照阶段**；整个键不写时，脚本会拿它**内置的示例角色卡**顶上去，并在开工时打印警告——那是最容易发生的"以为在跑自己的歌、其实在用示例角色卡"；写成数组这类非对象，`IDS.update()` 直接抛错。 |

## 每镜字段

| 字段 | 必填 | 说明 / 填错会怎样 |
| --- | --- | --- |
| `key` | 必填 | 镜的唯一名，决定四类文件名：关键帧 `kf_<key>_0.png` / `kf_<key>_1.png`、派生帧 `kf1x_<key>.png`、片段 `shot_<key>.mp4`、候选 `shot_<key>_<n>.mp4`。缺了生成器取 `s["key"]` 就崩；两镜重名会让素材互相覆盖，`chain_prev` 指过去也分不清指的是哪一镜。 |
| `t0` / `t1` | `t0` 必填 | 时间轴（秒）。合成器按 `t0` 排镜：**本镜的镜窗末端就是下一镜的 `t0`**（末镜改用 `t1` 或 `ZDN_TOTAL`）。生成器用 `t1 - t0` 估算这一镜要出多少帧（留 0.5s 余量，下限 121 帧≈5s、上限 249 帧≈10.4s，所以别指望靠 `t1` 把单镜拉得很长）。`t0` 重复或倒序时，合成器排序后会出现 0 长镜窗，整镜被吞掉；`t1` 与下一镜 `t0` 冲突时，多出来的素材不会播、不够的部分靠末尾轻微放大兜底（上限 1.18×，再长就是静止画面＝"幻灯片感"）。 |
| `lyric` | 必填 | 这一镜对上的那句歌词。它只进台账（`<bank>_clip_meta.json`）与人工核对，**不参与合成**；但缺了会在这一镜视频出完之后、写台账那一步 KeyError——素材已经落在盘上、state 也记了 done，重跑时这一镜会被直接跳过，台账里**永远缺这一镜**。 |
| `time` | 必填 | `lyric` 的可读时间，如 `"0:03.6"`。同 `lyric`：只进台账，但失败时机一样靠后。 |
| `style` | 必填 | 景别（全景/中景/特写……）。进台账，供人工核对"同一景别有没有连排"。 |
| `seconds` | 必填 | 这一句歌词的演唱时长。进台账。 |
| `keyframes` | 必填 | 提示词数组，**生成器真正读的那一份**：有几条就出几张 `kf_<key>_<i>.png`，但出片只取第 0 条当锚帧——第二关键帧由 `kf1_prompt` 经 i2i 从首帧派生（`kf1x_<key>.png`，`SKILL.md` §5 #13），第 1 条及以后照常出图、留在关键帧目录里，脚本不会读它们。**不要只改 `keyframe_prompt`**：那份是给人读的，脚本不读，改了等于没改（`SKILL.md` §5 #33）。 |
| `i2v_prompt` | 必填 | 图生视频提示词。按 `SKILL.md` §6.2 的"锁"组织：运动锁必写，有位移的写方向锁，有人物的写结构锁，构图锁全片常驻。只堆形容词、不写"画面里哪个元素怎么动"，出来的就是幻灯片或双头/倒退这类畸形。 |
| `kf1_prompt` | 动作镜必填 | 第二关键帧"推进到哪里"：一句话写清方向与推进量。缺了会退回取 `i2v_prompt` 的第一句，而第一句常常是相机或环境描述——i2i 于是在没有人、没有方向的情况下"推进"，实测会把人物整段丢掉或凭空长人（`SKILL.md` §5 #13/#23）。 |
| `chain_prev` | 可选 | 链式镜：填**上一镜的 key 字符串**（如 `"A1-1"`），i2v 就改用"上一镜尾帧 ＋ 本镜首帧"当垫图，用来接住跨镜的连续动作。填布尔会被**静默忽略**（`True in key2shot` 为假 → 按普通镜处理，不报错也不链式），这是最难查的一类"填了没生效"；指向不存在的 key 同样静默降级。链式镜不再派生 `kf1x`，`--kf-only` 也会跳过它。 |
| `src_offset` | 可选 | 秒数：合成器取素材时跳过开头这么多秒。素材的解剖畸形常集中在开头，这是"掐掉畸形段"的标准修法之一（`SKILL.md` §5 #34）。缺省 0 ＝ 旧行为；填非数字字符串会在合成抽帧时崩。 |
| `candidates` | 可选 | 每镜提交几条 i2v 候选，默认 2。生效值会被 `ZDN_CAND`（默认 9）压上限、被 1 抬下限：`max(1, min(candidates, ZDN_CAND))`。免费额度吃紧时把 `ZDN_CAND` 调小即可，不用动分镜库。 |
| `negative_extra` | 可选 | 追加到全库 `negative_prompt` 后面的逐镜负向词。拼接是**裸字符串相加、中间没有分隔符**，所以开头要自己带 `", "`：写成 `"文字"` 会得到 `"…车轮倒转文字"`，多出来的那个词等于没写。 |
| `kf1_lock_mode` | 可选 | 派生帧用哪把锁，取值 `none` / `hands` / `sil` / `crowd` / `people`，缺省 `people`。无人空镜用 `none`、手部镜用 `hands`、恰好两个剪影用 `sil`、远景人群用 `crowd`。填了别的值（包括大写 `None`）会**静默落到 `people`**，也就是"人物一个都不能少、一个都不能多"——无人镜被这句话逼着凭空画一个人（`SKILL.md` §5 #23）。 |
| `ui` | 可选 | 额外图层参数（行情网格、界面之类），交给可选的 `ui_layer` 模块渲染。仓库里没有这个模块时整段被跳过、不影响出片；它属于你自己项目的外挂件，写成什么形状由那个模块决定。 |

## 一份最小可跑的分镜库

单镜骨架，字段都是脚本真正必读的那些（提示词内容自己填）：

```json
{
  "_meta": {
    "style_prompt": "〈画风串：风格写在最前，例：唯美二维动画，赛璐璐平涂……〉",
    "ids": {}
  },
  "negative_prompt": "文字, 水印, 双头, 多手, 多指, 倒放, 原地踏步, 反复横跳, 车轮倒转",
  "shots": [
    {
      "key": "A1-1",
      "t0": 0.0,
      "t1": 3.6,
      "lyric": "（示例）第一句",
      "time": "0:00.0",
      "style": "全景",
      "seconds": 3.6,
      "keyframes": [
        "竖版 9:16 竖构图，画面正立。〈画风串〉〈这一镜首帧画什么，写清景别、主体、构图〉"
      ],
      "i2v_prompt": "【运动锁】〈画面里哪个元素怎么动，只写画面里真实存在的东西〉。【构图锁】竖版 9:16 竖构图，地平线保持水平。"
    }
  ]
}
```

`lyric` / `time` / `style` / `seconds` 只进台账，看起来可以省——**不要省**：
生成器是在**这一镜视频出完之后**才写台账的，缺一个就在那一步 KeyError——素材已经落在盘上、
state 也记了 done，重跑时这一镜会被直接跳过，台账里永远缺这一镜。想先验证管线本身，
`python tests/smoke_offline.py` 会用 `examples/song-a-bank.json` 在本地零成本跑一遍。

## 三条纪律

1. **`keyframes` 与 `keyframe_prompt` 两份要同改。** 出图读的是 `keyframes[i]`，
   `keyframe_prompt` 只是人读的副本；只改后者，这次改动等于没发生（`SKILL.md` §5 #33）。改完回读断言。
2. **`chain_prev` 是字符串**（上一镜的 key）。填布尔不会报错、也不会链式——它会在
   `chain_prev in key2shot` 那一步为假然后被当成普通镜，是最典型的"静默失效"。
3. **镜窗的 `t0` 要锚定演唱断句，不要用均匀网格。** 歌词句长在 1.7–5.0s 之间浮动，
   按"段内均匀网格"铺会在段中越走越偏（实测 47 个可比对镜里 35 镜偏差 ≥1s），
   观众看到的是"开着口型的画面已经过去了"（`SKILL.md` §5 #35）。`t0` 直接取该镜那句歌词的起唱时间。
